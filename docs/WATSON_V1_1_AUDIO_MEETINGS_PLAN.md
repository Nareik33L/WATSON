# WATSON V1.1 — Audio Processing & Meeting Intelligence: Engineering Plan (Revision 2)

**Supersedes:** WATSON V1.1 Product Scope — Audio Processing & Meeting Intelligence (v1.1, proposed). Position in the release ladder: V1.0 personal build → **V1.1 meetings** → V1.2 commercialisation (see `docs/ROADMAP.md`).
**Depends on:** `WATSON_V1_ENGINEERING_PLAN.md` (Revision 2) — the claims/evidence memory model, retention tiers, job queue, runtime adapters, replay harness and eval gates defined there are reused, not duplicated.
**Status:** Proposed engineering baseline

The product scope, retention policy, exclusions and acceptance criteria of the original scope document stand. This plan changes how it is built so that meetings are a *second source* into the existing memory engine rather than a parallel subsystem, and it closes several gaps the scope does not address: long transcripts that exceed a local model's context, speaker attribution without diarization, Whisper's well-known hallucination modes, audio decoding without a bundled ffmpeg, and the fact that the imported file is a copy of a recording the employee still holds elsewhere.

## 0. Summary of changes from the original scope

| Area | Original scope | Revision 2 | Why |
|---|---|---|---|
| Position in architecture | New "meeting processor" with its own summaries | Meetings are a **source** producing segments → observations → **claims + evidence**, like screen capture | One memory model, one search, one correction loop, one deletion path; weekly reports and Ask WATSON get meetings for free |
| When audio is deleted | After summarisation and persistence (step 9) | **As soon as the transcript is durably persisted** | Audio is the most sensitive artefact; the transcript is sufficient to retry every later stage |
| Transcript retention | Delete after successful processing | Delete after summary persisted (default), with an **opt-in tier-2 grace window** identical to screen text | Lets a user who corrects a summary ask for re-summarisation; default remains immediate deletion |
| Evidence | "Summary, key points" | Each claim carries **≤ 200-char verbatim quote with `start_ms–end_ms`** | Provenance without a transcript archive; "where did this come from?" has an answer |
| Long meetings | Not addressed | **Chunked map-reduce** extraction (~10-min windows with overlap) then cross-chunk consolidation | A one-hour meeting is 12k+ tokens; local models have 8k–32k contexts and degrade long before the limit |
| Speaker attribution | "Participants where reliably identifiable" | **No automatic diarization in V1.1.** Participants are user-entered or explicitly named in speech; first-person commitments are `unconfirmed` owner until the user confirms "that was me" | Local diarization (pyannote) is heavy, PyTorch-based and gated behind an online account; unreliable attribution is worse than none |
| Transcription engine | "Whisper" | `TranscriptionRuntime` adapter; **whisper.cpp (Core ML/Metal) or mlx-whisper** chosen by bake-off; openai-whisper (PyTorch) excluded from the package | PyTorch adds >1 GB and no Metal acceleration path we would ship; whisper.cpp/MLX are fast and bundle cleanly |
| Hallucination control | Not addressed | **VAD pre-pass**, no-speech/compression-ratio gating, repetition-loop detection, silence fixture in CI | Whisper invents text on silence and music ("Thanks for watching") and loops on long files |
| Audio decoding | Implicit (ffmpeg) | **AVFoundation via the Swift helper** → 16 kHz mono PCM | No ffmpeg to bundle/license; handles m4a, mp3, mp4, mov, caf, aiff, wav natively |
| Microphone | "No unauthorised microphone access" | **No microphone code path at all**; the bundle has no `NSMicrophoneUsageDescription`, so macOS cannot grant it | A verifiable guarantee for IT, not a policy statement |
| Original file | Not addressed | Import **copies**; UI states that the original remains where it was and offers "move original to Trash after success" (opt-in) | Deletion claims must be accurate about what WATSON controls |
| Consent | "Must be followed" | **Attestation checkbox on import**, recorded in `audit_events` with file hash and participants entered | Makes the policy requirement an auditable act |
| Testing | "Test processing failures…" | **Synthetic meeting fixtures** generated by macOS TTS from scripted fictional dialogues with ground truth; WER, P/R and zero-invention gates in CI | Offline, free, repeatable, no real voices |

## 1. Key decisions

### A1 — Meetings are a source, not a subsystem

Rev 2 already defines: `segments` → `observations` → `claims` with `evidence`, entity resolution with aliases, day consolidation, retention tiers, corrections, citations. A meeting is a new `source_type` whose segments are time-coded transcript windows instead of screen frames. Everything downstream (projects, people, commitments, achievements, daily/weekly/monthly reports, Ask WATSON, deletion) applies unchanged.

Consequences:

- The "Meeting summary" of §5 in the scope is a *rendering* of the meeting's claims plus user-entered metadata, exactly as the daily summary is a rendering of a day's claims.
- A commitment made in a meeting is the same row type as a commitment seen on screen; later screen evidence (a sent email, a published document) can be proposed as its completion.
- Deleting a meeting deletes its claims, evidence and links through the same cascade as deleting a day.

### A2 — Delete the audio early, the transcript on success, quotes forever

Three artefacts, three lifetimes:

| Artefact | Tier (Rev 2 §5) | Deleted when |
|---|---|---|
| Imported audio copy + decoded PCM | 0 | Transcript rows committed and `PRAGMA wal_checkpoint` done; deletion verified by `stat`; audit row |
| Full transcript (`meeting_transcript_segments`) | 2 | Summary/claims committed — **default immediately**; optional grace TTL (0–7 days) if the user enables "allow re-summarisation", excluded from FTS/embeddings as in Rev 2 |
| Evidence quotes (≤ 200 chars, with time range) | 3 | Life of the claim |
| Claims, rendered summary, metadata | 4 | User deletion or rolling window |

This is stricter than the scope on audio (gone after transcription rather than after summarisation) and identical to it on the transcript by default.

### A3 — Chunked extraction with cross-chunk consolidation

Transcripts are windowed into ~10-minute segments (≈ 1,200–1,800 tokens) with 60 s overlap. Each window runs the understanding prompt and returns candidate claims with quotes and timestamps. A consolidation pass receives *only the candidate claims* (not the transcript), merges duplicates across overlaps, resolves entities, and produces the meeting-level sections. Both passes use schema-constrained output and the Rev 2 citation verifier; a claim whose quote cannot be found verbatim (after whitespace/punctuation normalisation) in the transcript window is downgraded to `unconfirmed` and flagged.

### A4 — Speaker attribution is explicit or absent

Without diarization the model cannot know who said "I'll send the pricing by Friday." Rules:

- `people` for a meeting = user-entered participants ∪ names explicitly spoken/addressed in the transcript (`observed`, with the quote as evidence).
- A commitment's `owner` is set only when the transcript names the owner ("Priya will…", "can you, Tom, …" followed by assent). First-person commitments get `owner = unknown_speaker`, `assertion = unconfirmed`, and the Meetings page shows "Was this you?" with one-click confirm → `user_confirmed`, owner = employee.
- Decisions require explicit agreement language; proposals and open questions are classified as `discussion_point`, not `decision`.

Speaker diarization is recorded as an open decision for V2.0, with the pyannote licensing/online-gating constraint noted.

### A5 — Whisper via adapter; whisper.cpp or MLX in the package

`intelligence/runtime/transcription.py` defines `TranscriptionRuntime.transcribe(pcm16k, language_hint) -> list[TranscriptSegment(start_ms, end_ms, text, avg_logprob, no_speech_prob, compression_ratio)]`. Implementations evaluated at the bake-off: `pywhispercpp` (whisper.cpp with Core ML encoder and Metal), `mlx-whisper`, `faster-whisper` (CTranslate2, CPU-only on macOS, as fallback). Apple's on-device `SFSpeechRecognizer`/`SpeechAnalyzer` is listed as a future adapter but not relied upon because of locale/version constraints.

Model sizes are configuration; the bake-off chooses a default per RAM profile (expected: `base`/`small`-class on the 8 GB V1 machine, `small`/`medium` on 16 GB, a `large-v3-turbo`-class model on 24 GB+) and records real-time factor, WER on fixtures and peak RSS. On 8 GB, Whisper and the LLM cannot be resident together, so the pipeline must fully unload the transcription model before summarising; V1.1 therefore depends on the sequential-loading governance delivered in V1 M7.

### A6 — Hallucination and quality gating

Before transcription: Silero VAD (small ONNX, in-process) removes silence and music; audio is transcribed in VAD-bounded chunks ≤ 30 s so Whisper's long-form drift does not occur.
After transcription: segments with `no_speech_prob > 0.6` or `compression_ratio > 2.4` or avg log-prob below threshold are dropped and counted; a repetition detector removes n-gram loops. Counts surface in the meeting's "Uncertainties" and in metrics. A silence-only fixture and a music-only fixture must produce an empty transcript.

### A7 — Decoding in the Swift helper

`watson-capture` gains an `audio decode <in> <out.pcm>` subcommand using AVFoundation/`AVAssetReader` to produce 16 kHz mono 16-bit PCM and emit duration, channel count, codec and embedded creation date (used as the default meeting date). This avoids bundling ffmpeg, stays under the same code signature, and supports every container macOS can play. Stereo recordings are downmixed; multichannel files preserve per-channel transcription only if a future diarization-by-channel feature needs it (not in V1.1).

### A8 — Scheduling and resource governance

Meeting jobs run in the existing inference worker with **lower priority than live frame extraction** and never concurrently with the VLM (memory). Whisper and the LLM are loaded sequentially, not together, on every profile up to 16 GB. Progress is reported per stage with percentage (VAD chunk count gives transcription progress; chunk count gives summarisation progress). Battery/thermal policy defers meeting processing to AC power unless the user forces it.

## 2. Processing pipeline and state machine

```
imported ──► decoded ──► transcribing ──► transcribed ──► summarising ──► summarised ──► linked ──► completed
    │            │            │                │               │               │             │
    └────────────┴────────────┴────────────────┴───────────────┴───────────────┴─────────────┴──► failed(stage, error)
                                                 ▲
                                      audio + PCM deleted here, verified, audited
                                                                                              ▲
                                                                           transcript deleted here (unless grace enabled)
```

Stage detail:

1. **imported** — file copied into `spool/meetings/<meeting-id>/source.<ext>` (0600), SHA-256 recorded, consent attestation and user metadata (title, date/time, participants, project hint) stored, Spotlight excluded (`.metadata_never_index`), backup excluded. Validation: supported container, duration ≤ configured max (default 3 h), size ≤ configured max (default 2 GB), non-zero audio track.
2. **decoded** — helper produces PCM + metadata; source is kept until transcription succeeds (decode errors must be retryable).
3. **transcribing** — VAD → chunked transcription → quality gating → `meeting_transcript_segments` rows committed in one transaction with language detected and gating statistics.
4. **transcribed** — audio copy and PCM deleted, `stat` verifies absence, `audit_events(meeting_audio_deleted)` with byte counts. If "move original to Trash" was chosen, the original is moved now and audited; failure here is non-fatal and reported.
5. **summarising** — windowed extraction (A3), consolidation, citation verification.
6. **summarised** — claims, evidence, rendered summary committed; `pipeline_version`, `prompt_version`, `model_id`s recorded.
7. **linked** — working day resolved (created if the date has no capture), entities resolved/created as provisional, cross-source corroboration: screen segments in a meeting app overlapping the meeting time are linked as supporting context.
8. **completed** — transcript rows deleted (or `expires_at` set if grace enabled), verified, audited. Status shown as "Completed — temporary files deleted" per the scope's wording.

Failure at any stage preserves everything not yet superseded, records the stage and error, and exposes a retry action. Retries are idempotent via `jobs.idempotency_key = (meeting_id, stage, pipeline_version)`. Re-running summarisation after a user correction is only possible while a transcript exists (grace window) and is otherwise offered as "edit the summary manually".

## 3. Data model additions

| Table | Purpose | Key columns |
|---|---|---|
| `meetings` | One per imported recording | `working_day_id`, `title`, `started_at` (user/metadata), `duration_ms`, `source_hash`, `source_filename`, `source_bytes`, `language`, `state`, `failed_stage`, `error`, `consent_attested_at`, `original_disposition` (`left_in_place/moved_to_trash/trash_failed`), `audio_deleted_at`, `audio_deletion_verified`, `transcript_deleted_at`, `transcript_expires_at`, `gating_stats_json`, `pipeline_version` |

Changes to Rev 2 tables:

- `audit_events.kind` gains `meeting_imported`, `meeting_consent_attested`, `meeting_audio_deleted`, `meeting_transcript_deleted`, `meeting_deleted`, `meeting_original_trashed`.

## 4. Retention and deletion specifics

- The scope's requirement that temporary content never reach logs, analytics or backups is enforced by the Rev 2 `ContentField` log wrapper (transcript text, quotes and filenames are content), spool backup/Spotlight exclusion, and the absence of any analytics.
- **What "deleted" means** (documented in the Privacy page and the IT pack): WATSON unlinks its copies and verifies they are no longer present. On APFS with SSDs, overwrite-based secure erase is not meaningful; confidentiality of freed blocks relies on FileVault. WATSON does not and cannot delete the original recording unless the user opts in, and it says so at import time.
- Deleting a meeting from the dashboard removes `meetings`, participants, transcript (if any), segments, observations, claims, evidence, embeddings and FTS rows; re-renders any report that cited its claims with a "source removed" marker; writes one audit row with counts only.
- Deleting a day deletes its meetings. Deleting an entity unlinks meeting claims as in Rev 2.

## 5. Prompts and output schema

Two prompts, versioned under `intelligence/prompts/meeting_extract/` and `intelligence/prompts/meeting_consolidate/`:

**Extraction (per window)** receives: meeting title/date, user-entered participants, project hints with aliases, the window transcript with `[mm:ss]` markers, and the previous window's last 60 s. It returns candidate claims `{kind, text, assertion, quote, start_ms, end_ms, speaker_name_if_explicit, owner_if_explicit, deadline_if_explicit, confidence}`. Instructions encode the scope's accuracy rules: decisions need agreement language; deadlines must be quoted; "we should" is a suggestion, not a commitment; names only when spoken.

**Consolidation** receives only candidate claims and returns the meeting sections (summary, discussion points, decisions, commitments, project updates, potential achievements, uncertainties) as lists of claim IDs plus short connective text. Every sentence of the rendered summary cites claim IDs; the Rev 2 verifier strips uncited material into "Uncertainties".

## 6. Dashboard: Meetings section

- **Import**: drag-and-drop or file picker; shows detected duration, codec and embedded date; fields for title, date/time, participants (with autocomplete from `entities`), project hint; consent attestation checkbox (required); option "move original to Trash after successful processing"; statement of what will be retained and deleted.
- **List**: date, title, project(s), duration, state badge (scope's status names), deletion confirmation badge.
- **Detail**: rendered summary with claim badges (observed / inferred / unconfirmed / confirmed) and quotes with timestamps; "Was this you?" confirmations; edit with version history; participants with source labels; gating statistics ("4 min of silence skipped, 2 low-confidence segments dropped"); audit trail for this meeting; Delete.
- **Status bar** gains a meeting-processing indicator; the menu bar shows "Processing meeting (transcribing 42 %)".
- Meetings appear in Today/History timelines, in Projects and People histories, in search, in Ask WATSON answers and in weekly/monthly reports without new UI.

## 8. Testing and evaluation

### 8.1 Synthetic meeting fixtures

`tools/fixture_gen/meetings/` turns scripted fictional dialogues (YAML with speaker, line, optional stage direction) into audio using macOS `say` with distinct voices per speaker, mixed with silence gaps and optional background noise, plus `truth.yaml` listing participants, decisions, commitments (with owner and deadline), project updates, discussion points and deliberate traps (a suggestion that is not a decision, a deadline mentioned then retracted, a name mentioned who was not present). Fixtures ship for: a 12-minute stand-up, a 45-minute customer call, a 90-minute workshop (exercises chunking), a silence-only file, a music-only file, a corrupt file, an unsupported container, and a 1-second file.

Fixtures are generated on a Mac and committed as audio plus transcripts so Linux CI can still run the LLM stages from the committed transcript when no transcription runtime is available.

### 8.2 Gates

| Metric | Target |
|---|---|
| WER on scripted fixtures (chosen model, 8 GB profile) | ≤ 20 % ; 16 GB profile ≤ 15 % (TTS audio; real speech will be worse and is dogfooded) |
| Decisions precision / recall | ≥ 0.85 / ≥ 0.70 |
| Commitments precision / recall | ≥ 0.85 / ≥ 0.70 |
| Commitment owner correct when explicit; `unconfirmed` when not | ≥ 0.90 ; 100 % |
| Invented deadlines, participants or decisions (not in truth) | **0** |
| Claims with verbatim-verifiable quote | 100 % (structural) |
| Silence/music fixtures produce transcript text | 0 segments |
| Duplicate claims across chunk overlaps | < 5 % |
| Audio deletion verified for every `transcribed+` meeting | 100 % |

### 8.3 Failure and privacy tests

- Kill worker during transcribing / summarising / linking → source or transcript preserved, state `failed(stage)`, retry completes, no duplicate claims.
- Disk full during transcript commit → audio retained, no partial rows.
- Corrupt/unsupported/empty inputs → `failed(decoded)` with clear message, file retained for user inspection then deletable.
- No-network test covers the meeting pipeline end to end.
- Log scan: no transcript text, quote or source filename at any log level.
- Bundle inspection: `NSMicrophoneUsageDescription` absent; no `AVAudioSession`/`AVCaptureDevice` audio-input symbols linked in the helper.
- "Move original to Trash" moves exactly the selected file and only after `completed`.

### 8.4 Dogfooding

Before the milestone closes, the developer processes several recordings of fictional meetings read aloud by colleagues who have consented, on the development Mac, and reviews summaries against their own notes.

*Acceptance:* the author has processed ten real authorised recordings on the 8 GB Mac with the UI responsive and every one reaching "Completed — temporary files deleted"; the 90-minute fixture completes within 25 minutes on 8 GB (15 minutes on the 16 GB profile); privacy and failure suites pass, and against the packaged binary once V1.2 produces one.

## 10. Risks

| Risk | Mitigation |
|---|---|
| Real-world audio (crosstalk, accents, laptop mics) far below fixture WER | Dogfood early; expose confidence gating stats; "Uncertainties" section; model size configurable |
| Users expect "who said what" | Explicit A4 behaviour in the UI; participants field at import; diarization tracked for V2.0 |
| Long meetings exhaust memory alongside live capture | Sequential model loading, priority below frame extraction, AC-power deferral |
| Whisper hallucinated text becomes a "decision" | VAD + gating + quote verification + zero-invention gate |
| Teams/Zoom cloud recordings include consent banners/chat exports the user forgets | Import is per-file with attestation; documentation on what to export and what WATSON ignores |
| Grace-window transcripts become a de facto archive | Default off, max 7 days, excluded from search, visible on Privacy page with purge-now |
